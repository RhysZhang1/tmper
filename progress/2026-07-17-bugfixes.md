# 2026-07-17 Bug 修复

## Bug 1: 自动切歌时异常打开帮助页面

**症状**: 播放完一首歌自动切换到下一首时，键 0 帮助页面异常弹出。

**根因分析**:
1. Kitty 封面渲染器 (`render_kitty`) 未检查 `show_help` 状态 — 当帮助页面显示时，Kitty 转义序列仍被写入 stdout
2. 自动切歌时状态转换频繁（旧轨停止、新轨加载、封面更新），直接写入 stdout 的转义序列可能被某些终端（特别是 Konsole）误解析为输入事件
3. 缺少防御性重置：`on_track_ended` 未清理浮层状态

**修复**:
- `src/ui/cover/mod.rs`: Kitty 渲染器增加 `show_help || command_mode` 检测（与 chafa 渲染器行为一致）
- `src/app/playback.rs`: `on_track_ended` 开头增加 `self.ui_state.show_help = false` 防御性重置

## Bug 2: 左右箭头快进快退导致音量异常增大

**症状**: 在播放器界面按 ←/→ 快进快退后，音量突然跳到 100%，需按音量键才能恢复。

**根因分析**:
`AudioEngine::seek_relative()` 内部调用 `output.stop_and_replace()` 创建全新的 `rodio::Sink`，新 Sink 默认音量为 1.0 (100%)。但 `AudioEngine` 未缓存当前音量，无法在替换 Sink 后恢复用户设定的音量。

**修复** (`src/audio/engine.rs`):
1. 新增 `current_volume: f32` 字段到 `AudioEngine`
2. `new()` 中初始化为 0.8（与默认配置一致）
3. `set_volume()` 改为 `&mut self`，同时缓存值与应用到 Sink
4. `play_file()` 和 `seek_relative()` 中 `stop_and_replace()` 后立即调用 `self.output.set_volume(self.current_volume)` 恢复音量
